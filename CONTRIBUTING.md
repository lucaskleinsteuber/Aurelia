# Contributing to Aurelia

Search existing issues before opening one. For changes that affect several clients,
the server API, or stored data, discuss the approach in an issue before writing the
patch. Keep pull requests focused on one problem.

Start with the platform guide in the [README](README.md) and follow the
[repository rules](AGENTS.md) for building and testing. Run the checks for the
components you change. Use synthetic libraries and credentials, and keep real media,
private logs, tokens, and signing material out of issues and pull requests.
Describe what you verified and which platforms you could exercise.

Use the [issue templates](.github/ISSUE_TEMPLATE/) for bugs and feature requests.
For potential vulnerabilities, follow the [security policy](SECURITY.md).
